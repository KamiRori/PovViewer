# Phase 1 任务清单

范围以 `spec.md` 第 11 节为准：Electron、React、TypeScript、基础窗口、视频导入、POV 列表、视频网格。

本阶段结束时，用户能打开窗口，一次选入多个本地视频，看到按文件名生成的玩家卡片，并排成可切换列数的网格。卡片里的视频只加载元数据，不自动播放。

不要在本阶段做：Master Clock、播放/暂停/seek/倍速、offset 编辑、`sync.json`、同步播放、Focus、静音切换、全屏、搜索、`project.json`、FFmpeg、代理、打包安装器。

对应代码边界见 `docs/architecture.md`。类型和空目录可以按那份架构建好，但不要把 Phase 2 以后的交互做成能点的控件。

## 完成定义

- `npm run dev` 打开标题为 `Minecraft POV Viewer` 的窗口。
- 渲染进程没有 Node 集成；本地视频经 `pov://` 协议显示。
- Import POV 可多选 `.mp4` `.mkv` `.mov` `.webm`。
- 每个新文件成为一条 POV：名称来自文件名，重名自动加后缀，重复路径被忽略。
- 默认 4 列，可切到 2、3、4、5、6 列，网格自动换行。
- 名称可在卡片上修改。
- 卡片可以移出列表。
- 可播放文件显示画面并读出时长；不能播放的文件显示占位，程序不崩。
- 所有 `<video>` 静音、`preload="metadata"`、无 autoplay。
- 文件名规则有单元测试。

## 任务

按顺序做。前一步的验证没过，不开始后一步。

### 1. 工程骨架

- 用 electron-vite 建立 React + TypeScript 工程，目录符合 `docs/architecture.md` 第 2 节。
- 主进程窗口：标题 `Minecraft POV Viewer`，默认约 1280×800，最小约 960×600。
- `contextIsolation: true`，`nodeIntegration: false`，`sandbox: true`。
- 渲染进程入口只渲染一个空壳：顶栏标题 + 尚无 POV 的空状态。

验证：`npm run dev` 打开空窗口，关闭窗口后进程退出。开发者工具里 `process` 不可用。

### 2. 安全的本地媒体通道

- 实现 `selectVideoFiles()`：多选，过滤器包含 mp4、mkv、mov、webm。
- 实现媒体协议：主进程把已登记的绝对路径映射为 `pov://` URL。
- 未登记路径返回失败，不能靠猜 URL 读任意磁盘文件。
- Preload 只暴露这两个能力。

验证：用主进程日志或一次临时调用确认选中的路径能换成 URL。用未登记路径请求时失败。此步不必做完整个网格。

### 3. POV 模型与导入

- 定义 `POV` / `POVRuntime`（`spec.md` 第 5.1 节）。
- `project` store：导入、重命名、移除、设置列数。
- 纯函数：由路径得到 `playerName`；同一批与已有列表重名时追加 ` (2)`、` (3)`。
- 已存在的 `filePath` 再次导入时跳过。
- 新 POV 的 `offset = 0`、`enabled = true`、`muted = true`、`metadataReady = false`、`duration = 0`。
- 为文件名函数写单元测试：普通名、多后缀、无后缀、重名、Windows 路径分隔符。

验证：单元测试通过。此步可以用临时按钮把导入结果打在界面上，下一步再换成网格。

### 4. 网格与卡片

- 顶栏：`Import POV`，以及列数 2/3/4/5/6，默认 4。
- 空状态写明下一步是导入 POV。
- 卡片：玩家名（可编辑）、文件名、时长（元数据就绪后显示）、视频或占位。
- `loadedmetadata` 写回 `duration` 与 `metadataReady`。
- `error` 时占位为“无法直接播放”，列表保留该 POV，并提供移除。
- 视频元素：`muted`、`playsInline`、`preload="metadata"`，不调用 `play()`，不设置 `autoplay`。
- `enabled === false` 的条目不渲染。Phase 1 可以不做开关；导入结果一律 `enabled: true`。不要做搜索框。

验证：

1. 导入 1 个可播放 MP4，卡片名称与文件名一致，能看到画面，时长合理。
2. 再导入同一文件，列表不增加。
3. 导入第二个同名文件（不同目录），名称带 ` (2)`。
4. 把名称改成别的文字，刷新卡片标题。
5. 移除一张卡片后网格补位。
6. 列数从 4 改到 2 和 6，列数变化正确。
7. 导入一个 MKV 或明显不能播的文件时出现占位，窗口仍可操作。

### 5. 阶段验收

- 对照上面的完成定义再走一遍。
- 本机有足够样本时，一次导入接近 50 个 1080p MP4，确认进程不退出、窗口仍能滚动和改列数。导入后 CPU 不应处于“50 路同时在播”的状态；若任务管理器里解码明显持续跑满，检查是否误开了 autoplay。
- 没有 50 个样本时，在本清单底部记下实际导入数量，不把未测项标成通过。
- 确认 diff 里没有播放控件、sync 解析、项目保存、FFmpeg 依赖。

## 明确留到后面的接口

Phase 1 只放类型文件，不接 UI：

- `src/sync/types.ts`：`SyncResult`
- `src/timeline/`：可以没有运行代码。不要放一个会计时的假时间轴。

`player/VideoSurface` 若在 Phase 1 作为卡片里的视频标签封装，它只负责展示和元数据回调。不要写入校正、seek 或 `play()`。
